MESHLIT — PRIVACY POLICY
Version 2026-10-08.1 · Effective 8 October 2026
Maintainer: IMON · Project: https://github.com/sabbirimon/meshlit-v2

1. Scope and first use
This policy covers the Meshlit Android app and the separate Play review candidate. It describes the current implementation, not a promise about future adapters. Terms and Privacy acceptance is required before app use. Application-owned background bootstrap, model SDK initialization, startup model loading and audit startup wait for acceptance. Minimal local UI, logging, settings and dependency setup occur to show the agreement. You may decline and exit. The agreement is not consent to optional network services, audit collection or Android permissions.

2. What is stored locally
Meshlit may store conversations, prompts and attachments you choose, downloaded or imported model weights, model options, device profiles, task/job records, configuration, paired device details, allowlists, code workspace files, browser site permissions and diagnostic logs in its app storage or user-granted folders. It reads available device/OS information, memory, battery, thermal state, storage and network counters to support compatibility and monitoring. Not every local file is encrypted. Credentials and the opt-in audit journal use Android Keystore-backed encrypted storage; this does not protect against a compromised or unlocked device. System permissions remain controlled by Android.

3. Agreement record
Meshlit records the accepted Terms version, Privacy version and timestamp in installation-local preferences. This record is excluded from Android backup/device transfer with other preference files. Clearing app data or reinstalling requires acceptance again. Changing the policy version also requires new acceptance. The record is not sent to the maintainer, and no account is required for local text inference.

4. Optional online services and shared devices
When you choose a hosted model or media provider, relevant prompts, conversation context, attachments and provider credentials are sent to the configured provider as needed for that request. Model downloads and catalogs contact selected HTTPS hosts such as Hugging Face. Optional web search/crawlers, browsing, cloud inventory, pricing refreshes, SSH, MCP, OpenClaw, cluster workers and enrolled web/API nodes communicate with the hosts you configure. Depending on the operation, they may receive content, model artifacts, tensors, task data, commands, credentials or device/capability information. Browser pages and external accounts follow their own privacy policies. Read those policies and verify destination URLs before enabling integrations. External services may retain data and charge your account independently.

5. Credentials and permissions
API tokens, SSH credentials, reusable environments and collector headers are stored through encrypted credential stores. Service bindings and human/agent permissions are separate. Secrets should not be exported as ordinary configuration or audit metadata. File operations use explicitly granted storage access. Camera, microphone, location, nearby devices, notifications and optional cross-app Android control require separately chosen features and applicable Android grants. The Play review build removes the Accessibility service, device-wide VPN capture, SMS, broad storage/media grants and Termux command permission. This does not constitute Play approval.

Per-chat web-page and phone tool options default off. Enabled local planning uses the selected on-device model. Web requests send URLs and retrieve content through the separately configured HTTPS crawler host and its approved domains. Allowed Accessibility snapshots can contain ordinary screen text and are supplied to local planning; sensitive/protected input remains subject to the existing tool restrictions. Answers and source links may be retained in local chat history. These options do not enable a hosted model or enlarge OS grants.

Full builds can request Android-confirmed installation/removal and open another app's permission settings. A human-selected APK URI approval is remembered locally. APK bytes are staged in private app cache (at most four files, each up to 512 MiB); incomplete copies are removed, and files older than 24 hours are cleaned during a later install request. Android may reclaim cache sooner. No default upload is involved. File-picker grants can expire. The Play review build removes installation/removal request permissions and disables package administration. Android confirmation is not treated as a completed change, and silent root/device-owner/wireless-ADB administration is not implemented.

6. Optional audit telemetry
Audit collection is off by default. If enabled, a bounded encrypted local journal retains closed event metadata: time, source, actor class, action, outcome, pseudonymous hashed identifiers and allowlisted numeric measurements. It excludes prompt/reply content, task titles, raw tool arguments, passwords and token values at the collection and export boundaries. Identifier hashing is pseudonymization, not guaranteed anonymization. Retention is configurable from 1–90 days and 100–5,000 records. Batched writes and bounded queues can drop records; the journal is not a complete or tamper-proof compliance record.

The collector mode sends sanitized OTLP/HTTP traces and metrics to your saved endpoint using your encrypted, endpoint-bound headers. Resource data includes a local pseudonymous installation ID and service name. Grafana/collector service terms apply. The maintainer does not operate a default audit ingestion endpoint. Local JSONL/CSV exports go to the destination you select and are your responsibility. Disabling collection stops new scheduled collection; an in-progress batch may finish. Delete saved history separately in Audit and telemetry.

7. Third-party model SDK limitation
The current RunAnywhere development SDK has been observed attempting to contact its development telemetry endpoint during actual generation. The observed attempt failed DNS resolution; that is not proof of an effective opt-out or of the payload it would transmit. SDK development mode must not be treated as a telemetry opt-out. Meshlit's optional audit toggle does not control the SDK's own behavior. An upstream opt-out/data-flow review remains required before Play/public production release. Do not assume that all runtime paths are completely offline merely because local weights are selected.

8. Logs, exports and security
Ordinary diagnostic logs are distinct from redacted audit records and may contain URLs, errors or operational details. Review logs, screenshots, chat/file exports and browser/SSH output before sharing. Use platform screen locks, current OS updates, scoped credentials and trusted networks. Software security cannot be guaranteed. Meshlit does not intentionally sell personal data or include advertising code; third-party SDK and hosted-service behavior still requires review. No hosted account or network-capture proof is implied by a build or loopback test.

9. Retention, deletion and external copies
Local chats, tasks, models, workspace files and settings generally remain until you delete them, clear app data or uninstall. Downloaded files and exports in shared/user-granted folders may survive uninstall. Audit limits apply only to the app's audit journal. Android backup excludes shared preferences and native checkpoint files; other eligible app files may be backed up according to platform/account settings. Removing local credentials does not revoke an external token. Remote providers, clusters, cloud resources, browsers and export recipients retain their own copies; manage deletion and revocation with each service. External credentials should be rotated if exposed.

10. Updates and contact
Material document changes use a new version and require agreement again at launch. The public copy is https://github.com/sabbirimon/meshlit-v2/blob/main/docs/PRIVACY_POLICY.md. IMON maintains the project. For a non-sensitive privacy question or to request a private communication channel, use https://github.com/sabbirimon/meshlit-v2/issues. Never post personal data, credentials or private conversation content in a public issue. A dedicated private support/privacy contact, final SDK disclosures and Play Console Data safety answers are still required before store publication.
